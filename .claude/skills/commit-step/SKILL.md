# 작업 단위 커밋

과제가 **"한 번에 몰아 커밋하지 말고 작업 단위로 나눠 커밋"** 을 명시적으로 요구한다. 평가자가 히스토리를 읽는다.

## 절차

1. `git status --short && git diff --stat` 으로 변경을 본다.
2. **논리 단위를 센다.** 두 개 이상이면 쪼개서 여러 커밋으로 제안한다. 예시 경계:
   - 레이어가 다르다 (`data/` 파싱 추가 ↔ `ui/` 화면 구현)
   - 기능이 다르다 (정렬 ↔ 토스트)
   - 성격이 다르다 (기능 ↔ 리팩터 ↔ 문서 ↔ mock 데이터)
   한 커밋에 화면 코드와 무관한 리팩터·문서를 섞지 않는다.
3. `flutter analyze` 와 `flutter test` 를 돌린다. **경고나 실패가 있으면 커밋하지 않고 먼저 보고한다.** 로직이 새로 들어간 커밋인데 테스트가 없으면 그것도 짚는다(`.claude/rules/testing.md`).
4. 커밋별 메시지 초안을 만든다.
   - 형식: `feat|fix|refactor|style|docs|test|chore: <한국어 제목>`. scope 는 붙이지 않는다.
   - 제목은 무엇을 했는지, 본문(필요할 때만)은 **왜** 했는지.
   - **`Co-Authored-By` 등 AI attribution 라인을 붙이지 않는다.**
5. 쪼갠 계획과 메시지를 사용자에게 보여주고 **승인을 받은 뒤** `git add <파일들> && git commit` 을 단위별로 실행한다. 승인 없이 커밋하지 않는다.
6. 푸시는 사용자가 요청할 때만.

## 금지

- 푸시된 커밋에 `--amend`, `rebase`, `push --force` 를 쓰지 않는다. 요청받으면 이유를 설명하고 **새 커밋**을 제안한다. (`push --force` 와 `reset --hard` 는 settings.json 에서 차단되어 있다)
- `git add -A` 로 묶어 커밋하지 않는다. 쪼갠 단위대로 파일을 지정한다.
- `assets/mock/` 은 커밋 대상이다. 제외하지 않는다.

## 메시지 예

```
feat: 관심 화면 정렬 바텀시트 추가

시세를 아직 못 받은 행은 현재가순·등락률순에서 맨 아래로 보낸다.
값 없는 행을 0으로 치면 하락 종목처럼 보이기 때문.
```

```
fix: 일별 시세 EUC-KR 디코딩 누락으로 종목명 깨짐
refactor: 등락 텍스트를 ui/common 으로 승격
docs: 아키텍처 결정 기록 추가
test: 일별 시세 파서 유닛 테스트
chore: 실시간 시세 mock 응답 추가
```
