# 진행 플로우

오늘 **2026-09-11**, 마감 **2026-09-14 23:59**. 공식 기간 09-11 ~ 09-14 의 첫날이다. 09-10 은 준비로 벌어둔 하루였고, 거기서 못 끝낸 3건은 Phase 1 맨 앞으로 이월했다.

## 원칙

1. **필수를 먼저 전부 채운다.** 선택 항목은 필수가 다 끝난 뒤에만 손댄다.
2. **Fake 는 순서일 뿐 종착지가 아니다.** endpoint 는 호출이 잦으면 막히니 mock 으로 파싱을 먼저 확정한다. 다만 **완료 기준은 실제 endpoint 연동**이다 — 각 화면은 `USE_FAKE` 없이 값이 들어오는 걸 확인해야 끝난 것으로 친다.
3. **판단은 즉시 기록.** Figma 에 없는 것을 결정할 때마다 `README.md` "직접 판단한 부분"에 한 줄. 마지막에 몰아 쓰면 반드시 빠뜨린다.
4. **작업마다 브랜치, 커밋은 작업 단위로.** `main` 직접 커밋 금지 — 새 브랜치에서 작업하고 PR 로 올린다. 각 단계 아래 커밋 포인트를 적어 뒀고 `/commit-step` 으로 쪼갠다.
5. **막히면 다음으로 넘어간다.** 한 항목에 1시간 이상 붙잡히면 남겨두고 진행한 뒤 `flutter-app.md` 에 표시한다. 요구사항 자체가 모호하면 안내 메일 회신으로 문의할 수 있다(`brief.md`).
6. **체크박스는 끝나는 즉시 켠다.** `git push` 때 자동 생성되는 `.claude/HANDOFF.md` 가 이 파일의 체크박스로 "지금 어느 Phase 인지"를 판단한다. 안 켜면 다음 세션이 엉뚱한 데서 시작한다.

## 시간이 부족할 때 자르는 순서

위에서부터 먼저 버린다. 아래로 갈수록 버리면 감점이 크다.

1. 선택 항목 전부 (pull to refresh, 최근 검색어, 애니메이션, 무한 스크롤, 로컬 저장)
2. 차트 정교함 — 캔들만 색 맞춰 그리고 축 라벨·거래량 바·크로스헤어는 버린다
3. 레이아웃 테스트의 확대 폭(375 · 430)과 ViewModel 테스트 일부 — **유닛 테스트(포맷 · 파서 · 스토어)와 393 한 폭은 남긴다**
4. ~~필수 항목~~ — 버리지 않는다. 정말 못 하면 README 에 "무엇이 왜 남았고 어떻게 하려 했는지"를 적는다. 과제가 이걸 평가에 반영한다고 명시했다.
