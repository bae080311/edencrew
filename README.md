이든크루 Flutter 신입 개발자 평가 과제. 관심 · 검색 · 종목상세 세 화면을 Flutter 로 구현하고 Naver 금융 endpoint 4개를 연동한다. 다크 테마 단일 모드.

## 실행 방법

```bash
cd app
flutter pub get
flutter run              # 실제 endpoint 를 조회한다 (기본)
```

개발 중 네트워크가 막힌 구간에서는 저장해 둔 응답으로 돌릴 수 있다.

```bash
flutter run --dart-define=USE_FAKE=true    # assets/mock/ 의 응답을 같은 파서로 읽는다
```

- **Flutter 3.47.3 · Dart 3.13.3** (stable)
- **웹(Chrome)에서는 동작하지 않는다.** Naver endpoint 가 CORS 를 허용하지 않는다.
- 확인한 플랫폼과 기기: *(작업하며 채운다)*
- 레이아웃 기준은 Figma 프레임 `393 × 852` 이고, 창을 그 비율에 맞춰 확인한다.
- 폰트는 스타터가 등록해 둔 `Noto Sans KR` 을 그대로 쓴다. 바꾸지 않았다.

## 구현 범위

**데이터 계층 — 완료**

- endpoint 4개 요청 (`NaverApi`) · 파싱 · DTO 4종 · 앱 모델 연결
- 일별 시세 HTML 파싱 (`SiseDayParser`) — EUC-KR 디코딩, 표 컬럼 순서, 전일비 부호, `lastPage`
- 실시간 시세 **batch 조회** — 관심종목을 한 번의 요청으로 받는다
- 일별 시세 **페이지 캐시** — 기간에 필요한 만큼만 받고 받은 페이지는 재사용, `lastPage` 초과 요청 없음
- 숫자 · 날짜 포맷 단일 지점 (`core/format.dart`)
- 목업 전환 (`--dart-define=USE_FAKE=true`) — 실제 구현과 **같은 DTO · 파서**를 쓴다

**화면 — 관심 · 검색 · 종목상세 완료**

- 관심 — 목록 · 새로고침(batch 1회) · 스켈레톤 · 빈 상태 · 정렬 3종
- 검색 — 디바운스 · 검색어 강조 · 별 토글 · 토스트 2종 · 빈 상태 2종
- 종목상세 — 헤더 · 현재가와 등락 · 기간 탭 4개 · 캔들 차트 · 요약 카드 · 일별 시세 표
- 상태 동기화 — 세 화면이 `FavoritesStore` 하나를 본다

실제 endpoint 로 화면까지 값이 흐르는지 확인하는 일이 남았다(`USE_FAKE` 없이).

**테스트**

```bash
cd app && flutter test        # 150개 통과
dart run tool/check_endpoints.dart   # endpoint 4개 실제 응답 확인
```

포맷 · 파서 · DTO · 모델 · repository 를 유닛 테스트로 덮었다. 특히 **페이지 캐시는 요청 횟수를 세어 검증한다** —
`1개월 → 3개월` 전환 때 이미 받은 1 · 2 페이지를 다시 요청하지 않고, `lastPage` 를 넘는 페이지는 요청하지 않는다.

## 기술 선택과 이유

결정의 전체 목록과 근거는 [`ARCHITECTURE.md`](docs/ARCHITECTURE.md) 에 있다. 요약하면,

- **상태관리 · DI — `provider` + `ChangeNotifier`.** 화면 3개 규모에서 충분하고 상태관리와 의존성 주입을 같은 도구로 해결한다. Riverpod 은 이 규모에서 얻는 이득보다 개념 학습 비용이 크다고 판단했고, 주입 지점이 `main.dart` 하나여서 `get_it` 같은 DI 컨테이너도 두지 않았다.
- **HTTP — `http`.** GET 4개뿐이라 dio 의 인터셉터 · `CancelToken` · 재시도 · FormData 가 쓰이지 않는다. 요청 취소는 ViewModel 의 latest-wins 로 해결한다. 오히려 응답이 EUC-KR 이어서 `bodyBytes` 를 그대로 코덱에 넘기는 `http` 가 다루기 쉬웠다 — dio 는 기본이 자동 변환이라 `ResponseType.bytes` 설정을 되돌려야 한다.
- **EUC-KR 디코딩 — `cp949_codec`.** 아래 "직접 판단한 부분" 참고.
- **SVG 아이콘 — `flutter_svg`.** 시안 아이콘이 SVG 라 글리프를 그대로 쓰려고 넣었다. 유일하게 `provider` · `http` 밖에서 늘린 의존성이다. 자세한 이유는 아래 "직접 판단한 부분" 참고.
- **포맷 — `intl` 없이 `core/format.dart`.** 축약 단위(천 · 조)가 한국식 표기라 `intl` 로도 결국 직접 써야 해서 의존성을 늘릴 이유가 없다.
- **캔들 차트 — `CustomPainter` 로 직접 그렸다.** 패키지를 쓰면 캔들 색을 `chartLineUp`/`chartLineDown` 토큰으로 맞추고 시안의 여백 · 높이까지 끼워 넣는 일이 오히려 커진다. 그릴 것이 심지 선 하나와 몸통 사각형 하나뿐이라 `Canvas` 로 직접 그리는 편이 짧고, 의존성도 늘지 않는다.
- **디자인 토큰 — 값은 수정하지 않고 텍스트 스타일만 추가했다.** 스타터 토큰에는 글자 크기 · 행간이 없는데, Figma Variables 에 없을 뿐 이름 붙은 텍스트 스타일(`display/price` · `title` · `body` · `label` · `caption`)로는 정의되어 있었다. 화면마다 크기를 따로 적으면 같은 값이 흩어지므로 그 스타일을 `AppTypography` 의 `TextStyle` 상수로 1:1 옮겼다. 새 스케일을 지어낸 것이 아니다. `body/num` · `caption/num` 은 참조하는 family 변수가 `base` 와 같은 값이라 합쳤다. 대응표는 [`app/lib/theme/README.md`](app/lib/theme/README.md) 에 있다.

## 직접 판단한 부분과 이유

Figma 시안이나 과제 원문에 정의되지 않아 직접 결정한 것들. **결정할 때마다 한 줄씩 덧붙인다.**

- **EUC-KR 디코딩에 `cp949_codec` 을 썼다.** `dart:convert` 의 `Encoding` 을 구현해 `utf8` 과 같은 방식으로 쓸 수 있고, 순수 Dart 라 유닛 테스트에서 mock 파일을 그대로 디코딩해 검증할 수 있다. CP949 는 EUC-KR 의 상위집합이라 호환된다.
  후보 검토에서 셋이 탈락했다. `euc` 는 EUC-JP · Shift_JIS 전용이고, `charset_converter` 는 플랫폼 채널을 써서 위젯 바인딩 없는 유닛 테스트에서 돌지 않는다. `charset` 은 `eucKr` 코덱을 제공하지만 **디코딩이 깨져 있었다** — 내부 매핑 테이블 두 개의 이름이 서로 반대로 붙어 디코더가 역방향 테이블을 참조하고, `삼성전자` 가 `鋱鏋飜飅` 로 나온다. 패키지를 고른 뒤 실제 바이트로 한 번 돌려보고서야 발견했다.
- **디코딩은 일별 시세 HTML 뿐 아니라 실시간 시세 JSON 에도 적용한다.** `NAVER_API.md` 는 HTML 만 인코딩을 경고했지만, 실시간 시세 응답도 `Content-Type: text/plain;charset=EUC-KR` 로 내려와 종목명(`nm`)이 깨진다. 두 곳에서 같은 코덱을 쓴다.
- **등락액 · 등락률을 응답의 `cv` · `cr` 대신 `nv - pcv` 로 직접 계산한다.** 응답의 `cv` · `cr` 에는 부호가 없고 방향이 별도 코드(`rf`)에만 담겨 오기 때문에, 명세가 지시한 계산식을 쓰는 편이 정확하고 보합 판정도 한 곳에서 끝난다.
- **거래량 · 시가총액 축약은 버림한다.** 시안의 `29,113천` · `1,063조` 는 표기 형식만 보여주고 절삭 방식은 정하지 않았다. 반올림하면 실제보다 큰 값으로 보이므로 버림을 택했다.
- **등락률은 소수 2자리, 보합은 부호 없이 `0 (0.00%)` 로 표기한다.** 시안 예시가 `-400 (-0.22%)` 라 자리수를 따랐고, 0 에 `+` 가 붙으면 상승으로 읽히므로 보합에는 부호를 넣지 않았다.
- **시세를 받지 못한 종목은 결과에서 빼고 화면은 그 행을 스켈레톤으로 남긴다.** 관심 목록의 한 종목이 거래정지 등으로 값이 비어 올 때 목록 전체를 실패로 처리하면 나머지 종목까지 못 보게 된다. 과제가 이미 요구한 "아직 시세를 받지 못한 행" 표현과 같은 상태로 합쳤다.
- **일별 시세 표의 `등락` 은 HTML 의 방향 아이콘으로 읽는다.** 표는 전일비를 절대값으로만 보여주고 방향을 아이콘 class(`bu_pup` · `bu_pdn` · `bu_pn`)로 구분한다. 인접 행의 종가 차이로 계산하는 방법도 있지만 그러면 페이지의 가장 오래된 행에서 값이 비므로, 모든 행이 채워지는 아이콘 쪽을 택했다.
- **시세를 못 받은 행은 `현재가순` · `등락률순` 에서 맨 아래로 보낸다.** 값이 없는 행을 값 있는 행 사이에 끼우면 정렬이 어긋나 보인다. `가나다순` 은 이름이 있으니 그대로 줄을 세운다. (과제가 직접 판단하라고 지목한 항목)
- **`현재가순` · `등락률순` 은 내림차순이다.** 시안에 방향이 없어 큰 값 · 높은 등락률이 위로 오게 했다 — 목록에서 먼저 보고 싶은 쪽이다.
- **관심 목록은 종목명과 시장을 함께 들고 있는다.** symbol 만 저장하면 목록을 그릴 때마다 종목 수만큼 메타를 다시 조회해야 한다. 등록하는 화면(검색 · 상세)이 이미 그 값을 갖고 있어 함께 담았다.
- **새로고침이 실패해도 이미 받아둔 목록은 지우지 않는다.** 갱신 실패로 화면이 비면 사용자가 잃는 것이 더 크다. 처음 조회부터 실패한 경우에만 에러 상태로 바꾼다.
- **네트워크 타임아웃은 10초, 에러 문구는 `시세를 불러오지 못했습니다` 로 뭉갠다.** 사용자가 할 수 있는 일(다시 시도)이 하나뿐이라 원인별로 문구를 나눌 이유가 없다. 응답 형식이 어긋난 경우만 `시세를 읽지 못했습니다` 로 가른다.
- **일별 시세 표의 거래량은 축약하지 않는다.** 과제가 축약을 지시한 곳은 요약 카드의 `거래량` · `시가총액` 이고 표는 컬럼 이름만 정했다. 표는 날짜별로 값을 견주는 자리라 `6,448,323` 처럼 전체 숫자가 더 읽기 좋다고 봤다.
- **검색어 강조는 종목명의 첫 일치 구간 한 곳만, 영문은 대소문자를 가리지 않는다.** 종목명이 짧아 같은 글자가 여러 번 나오는 경우가 드물고, `naver` 로 검색해도 `NAVER` 가 강조돼야 자연스럽다.
- **검색 입력은 300ms 디바운스에 latest-wins 를 걸었다.** 한 글자마다 요청하면 자동완성 endpoint 를 불필요하게 두드리고, 늦게 도착한 옛 응답이 최신 결과를 덮는 문제도 막아야 한다. (디바운스 자체는 과제의 선택 항목)
- **시안 아이콘은 SVG 로 내보내 그대로 쓴다(`flutter_svg`).** Material 아이콘으로 대체하면 별 · 정렬 · 새로고침의 부피와 획이 시안과 어긋난다. 평가가 "Figma 와 최대한 가깝게"를 보므로 글리프를 맞추는 쪽을 택했고, 그 대가로 패키지 하나를 늘렸다. 색은 파일에 박힌 값을 `ColorFilter` 의 `srcIn` 으로 덮어 활성 / 비활성을 토큰으로 전환한다.
- **`Scale` 컬렉션에 없는 시안 값도 `AppDimens` 에 추가해서 쓴다.** 행 내부 간격 2, 탭 라벨 간격 3, 입력 필드 · 토스트 여백 10 · 14, 아이콘 18 · 22 · 24 · 40, 바텀시트 라운드 16 · 제목 영역 높이 64가 그렇다. 처음에는 대응표가 깨지는 게 싫어 위젯 안에 `const` 로 뒀는데, 그러면 같은 값이 화면마다 흩어져 "간격은 토큰으로만" 규칙이 무의미해진다. 대응표는 Figma 변수에서 온 것과 시안 레이어에서 읽은 것을 표로 갈라 적는 쪽으로 해결했다([`theme/README.md`](app/lib/theme/README.md)).
  다만 **스켈레톤 막대 크기(64×16 · 48×12)는 위젯 안에 남겼다.** 간격 · 반경 · 아이콘과 달리 한 위젯의 상자 크기라 다른 화면이 가져다 쓸 값이 아니다. 두 번째 사용처가 생기면 그때 올린다.
  **여백에는 이 예외를 적용하지 않는다.** 검색 입력 필드와 토스트의 여백도 같은 논리로 위젯에 두었다가 리뷰에서 되돌렸다. 규칙이 "간격은 `context.dimens.*` 만"이라고 이미 정해 둔 자리에서는 메모에 이유를 적는 것으로 비켜갈 수 없다.
- **로딩에 별도 화면을 두지 않는다.** 관심 목록은 종목명과 시장을 이미 들고 있어 조회 중에도 행이 그려지고 가격 자리만 비어 있다. 과제가 요구한 "아직 시세를 받지 못한 행은 스켈레톤" 표현이 그대로 로딩 표현이 된다. 스피너를 겹치면 같은 상태를 두 번 알리는 셈이다.
- **새로고침 중에는 아이콘을 `textDisabled` 로 낮추고 탭을 막는다.** 시안에 진행 표시가 없어 새로 그리지 않았고, 목록이 이미 보이는 상태라 누를 수 없다는 것만 알리면 충분하다고 봤다.
- **재조회가 실패해도 이미 받아둔 행은 남긴다.** 관심을 하나 더 등록해 목록을 다시 조회하다 실패했을 때 멀쩡한 행까지 전체 실패 화면으로 덮으면 사용자가 잃는 것이 더 크다. 쓸 수 있는 시세가 하나도 없을 때만 실패 화면을 보여준다 — 새로고침 실패와 같은 정책이다.
- **네트워크 실패 화면은 문구 한 줄과 `다시 시도` 버튼뿐이다.** 시안에 없는 상태이고 사용자가 할 수 있는 일이 하나라 선택지를 늘리지 않았다. 처음 조회부터 실패한 경우에만 이 화면이 뜬다.
- **긴 종목명은 한 줄로 자르고(`...`) 가격 영역 폭을 먼저 확보한다.** 종목명이 줄바꿈되면 행 높이가 들쭉날쭉해지고, 가격이 밀려 잘리면 목록의 쓸모가 사라진다. 확인은 `LG에너지솔루션우선주삼성바이오로직스` 같은 이름으로 `layout_test.dart` 에서 한다.
- **정렬 바텀시트의 딤은 `showModalBottomSheet` 기본값(검정 54%)을 쓴다.** 시안은 50% 지만 토큰에 없는 색이라 hex 를 직접 적는 대신 프레임워크 기본값을 두었다. 4% 차이는 눈에 띄지 않는다.
- **탭을 옮겼다 돌아와도 목록을 다시 조회하지 않는다.** `IndexedStack` 으로 두 화면의 상태를 유지한다. 시세 갱신은 새로고침 버튼이라는 명시적 동작으로만 일어나는 편이 예측 가능하다.
- **탭 바 높이에 `size/tabbar`(56) 토큰을 쓰지 않았다.** 시안의 `Tab bar` 프레임은 여섯 화면 모두 **63px**(상하 여백 8 + 탭 47)이다. 토큰 값을 강제하면 오히려 시안과 어긋나므로 프레임 값을 따랐다. `size/tabbar` 는 이 화면들에서 쓰이지 않은 토큰으로 보인다.
- **관심 등록 · 해제 토스트는 2초 노출한다.** 시안에 시간이 없다. 별 아이콘이 행에서 이미 바뀌므로 토스트는 보조 확인이고, 여러 종목을 연달아 등록할 때 앞 토스트가 다음 조작을 가리면 안 된다. 그래서 짧은 쪽을 택했다. (과제가 직접 판단하라고 지목한 항목)
- **토스트는 직접 `Overlay` 를 짜지 않고 `ScaffoldMessenger` 의 `SnackBar` 로 만들었다.** 노출 시간 · 등퇴장 애니메이션 · 탭 바 위 배치 · 연속 호출 처리를 프레임워크가 이미 한다. 배경 · 라운드 · 테두리 · 아이콘과 문구의 간격은 시안 값을 그대로 넣었고, **그림자만 `elevation: 8` 로 근사**했다(시안은 `0 8 24 rgba(0,0,0,.55)`). 그림자 색은 토큰에 없어 hex 를 직접 적는 대신 프레임워크 값을 썼다.
- **검색 입력의 클리어(×) 버튼은 입력 전에도 계속 보인다.** 시안의 `02 · 검색_empty` 프레임이 placeholder 상태에서도 이 버튼을 그려 두었다. 조건부로 감추면 입력할 때마다 버튼이 나타났다 사라져 폭이 흔들린다.
- **결과 없음 문구에서는 검색어 쪽을 20자에서 자른다(`…`).** 문구에 사용자 입력이 그대로 들어가는데 길이 제한이 없다. 문구 전체를 말줄임하면 정작 읽어야 할 `일치하는 검색 결과를 찾지 못했습니다.` 가 통째로 잘려 나간다. 자르는 자리는 검색어이고, 안내 문장은 항상 남는다. 빈 상태 설명은 그 위에 두 줄 제한을 한 겹 더 둔다. (과제가 직접 판단하라고 지목한 항목)
- **검색 중에는 이미 받아둔 결과를 그대로 두고, 결과가 하나도 없을 때만 스피너를 보여준다.** 한 글자마다 목록이 비었다 채워지면 읽을 수가 없다. 첫 조회에만 스피너가 보이므로 "검색 전" 빈 상태가 조회 중에 잘못 뜨는 일도 없다. (로딩 표시 자체는 과제의 선택 항목)
- **검색 결과 행의 별은 아이콘 영역만 탭 대상이다.** 행 전체를 관심 토글로 쓰면 상세 화면으로 이동하는 탭과 겹친다. 헤더의 새로고침 버튼과 같은 방식(`HitTestBehavior.opaque`)으로 맞췄다.
- **관심 목록 행도 누르면 상세로 간다.** 과제가 명시한 것은 검색 결과 행뿐이지만, 같은 모양의 행이 한쪽에서만 반응하면 고장으로 읽힌다. 두 화면 모두 `openStockDetail()` 하나를 부른다.
- **상세 화면의 현재가 옆 등락은 `▼ 400 (-0.22%)` 로 쓴다.** 시안이 방향을 화살표로 보여주고 등락액에는 부호를 붙이지 않았다. 목록 행(`-400 (-0.22%)`)과 표기가 다르므로 `core/format.dart` 에 `arrowChangeLabel` 을 따로 두었다. 보합에는 화살표가 없다.
- **상세 첫 조회에는 가운데 스피너 하나를 둔다.** 관심 목록과 달리 종목명 · 가격 · 표 어느 것도 미리 들고 있지 않아 스켈레톤으로 채울 형태가 없다. 빈 상자를 여러 개 그리는 것보다 조회 중임을 한 번 알리는 편이 정확하다.
- **기간 탭을 바꾸는 동안에는 이전 차트 · 표를 흐리게(`0.4`) 남긴다.** 비우면 탭을 눌렀다는 사실 말고는 아무것도 보이지 않고, 그대로 두면 바뀌는 중인지 알 수 없다. 요약 카드는 기간과 무관하므로 흐려지지 않는다.
- **기간 전환만 실패하면 화면을 유지하고 탭 아래에 한 줄(`feedbackWarning`)로 알린다.** 이미 보고 있던 구간까지 실패 화면으로 덮을 이유가 없다. 처음 조회부터 실패한 경우에만 `다시 시도` 화면이 뜬다 — 관심 화면과 같은 정책이다.
- **시세를 받지 못한 값 자리는 `-` 로 둔다.** 0 으로 채우면 실제 값처럼 보인다. 관심 목록은 행마다 스켈레톤을 쓰지만 상세는 한 종목의 값이 통째로 비는 것이라 자리만 표시했다.
- **상세 화면의 별 토글에는 토스트를 띄우지 않는다.** 시안의 토스트 프레임 두 개(`04` · `05`)가 모두 검색 화면이다. 상세에서는 헤더의 별이 눈앞에서 바뀌므로 같은 사실을 두 번 알릴 필요가 없다.
- **요약 카드 셀 폭을 시안의 `115` · `176.5` 고정 대신 균등 분배로 바꿨다.** 고정값을 쓰면 375 폭(SE)에서 한 줄에 들어가지 않는다. 시안의 배치(3칸 + 2칸)와 간격 8은 그대로 두고 폭만 `Expanded` 로 나눴다.
- **기간 탭 라벨은 `label`(13/18) 스타일에 굵기만 Regular 로 낮춰 쓴다.** 시안의 탭 라벨이 같은 크기 · 행간에 Regular 다. 13px Regular 스타일을 새로 만들면 토큰이 하나 더 늘어난다.
- **캔들 색은 전일비가 아니라 몸통 방향(종가 − 시가)으로 가른다.** 같은 행의 `tone`(전일비)을 그대로 쓰면 갭 상승 뒤 밀린 날 — 전일 종가 100 · 시가 110 · 종가 105 — 이 몸통은 내렸는데 상승 색으로 칠해진다. 몸통을 시가~종가로 그리는 이상 색도 같은 기준이어야 한다. 표의 `등락` 컬럼은 전일비 그대로다(`DailyPrice.tone` / `DailyPrice.candleTone` 으로 갈랐다).
- **캔들 심지는 `chartBaseline`, 몸통은 `chartLineUp`/`chartLineDown` 이다.** 시안(`03 · 종목상세` 의 각 캔들 열)이 심지를 `chart/baseline` 으로 칠해 두었다. 심지까지 방향 색으로 칠하면 캔들이 뭉쳐 보여 시안의 의도와도 어긋난다.
- **메타를 받기 전에는 상세 화면의 별을 누를 수 없다(`textDisabled`).** 이름 · 시장을 모르는 채로 등록하면 관심 목록에 종목코드만 남고, 나중에 메타가 도착해도 그 행은 고쳐지지 않는다. 조회 중이거나 실패한 상태에서만 잠기고 `다시 시도` 로 풀린다 — 새로고침 버튼을 조회 중에 막는 것과 같은 방식이다.
- **캔들 심지는 시안의 `0.3` 보다 두껍게 그린다.** 1년치 245개를 393 폭에 그리면 심지도 몸통도 사라진다. 캔들 간격 `1.2` 는 시안대로 두고, 심지 · 몸통에 최소 굵기 `0.8` 을 뒀다. 과제가 "차트 안쪽의 그림은 시안과 달라도 감점하지 않는다"고 명시한 범위다. 캔들 색(`chartLineUp` / `chartLineDown`)과 차트 높이 200 은 시안 그대로다.
- **일별 시세 표는 1년치 245행을 한 번에 만든다.** 표가 화면 본문의 일부라 `SliverList` 로 바꾸면 본문 전체를 sliver 로 쪼개야 한다. 245행 정도는 한 번에 만들어도 무리가 없어 `Column` 으로 두었고, 무한 스크롤(선택 항목)을 붙이게 되면 그때 바꾼다.
- **상세 화면의 상자 크기만 위젯에 `const` 로 남기고 여백은 전부 토큰으로 올렸다.** 차트 높이 200 과 표의 날짜 칸 46 은 스켈레톤 막대와 같은 기준으로 위젯에 두었다. 반면 앱 바 · 본문 · 탭 칩 · 요약 카드 · 표 행의 여백(10 · 14 · 5 · 10 · 9 · 3 · 7)은 `AppDimens` 에 추가했다 — 처음엔 이것도 "한 화면의 상자 값"이라며 위젯에 뒀는데, 검색 필드 · 토스트에서 이미 두 번 되돌린 실수다. `critical.md` 2번이 "간격은 `context.dimens.*` 만"이라고 못 박은 자리에서는 메모에 이유를 적는 것으로 비켜갈 수 없다.
- **`PriceTone → Color` 매핑을 `ui/common/` 으로 올렸다.** 관심 행에만 있던 코드인데 상세의 현재가 · 일별 시세 표가 두 번째 · 세 번째 사용처가 됐다. "상승 = 빨강, 하락 = 파랑"을 한 곳에서만 정한다.

## 막혔던 지점과 어떻게 접근했는지

- **macOS 앱에서만 조회가 전부 실패했다.** 데이터 계층 점검 도구(`dart run tool/check_endpoints.dart`)로는 endpoint 4개가 모두 응답하는데 앱에서는 검색 결과가 하나도 오지 않았다. 원인은 망이 아니라 **App Sandbox** 였다 — Flutter 의 macOS 템플릿은 `com.apple.security.network.server`(들어오는 연결)만 넣어주고 **나가는 연결(`com.apple.security.network.client`)은 켜주지 않는다.** 점검 도구는 샌드박스 밖의 Dart VM 에서 돌아 이 차이를 드러내지 못했다. 두 entitlements 파일에 권한을 추가하고, 빌드된 `.app` 에 실제로 박혔는지 `codesign -d --entitlements` 로 확인했다.
- **개발 망이 네이버 금융을 차단했다.** endpoint 4개 중 3개가 TLS 핸드셰이크 직후 연결이 끊겼다. HTTP 로 요청해 보니 응답 본문이 기관망의 차단 안내 페이지(`기본 차단 정책`)여서 서버 문제가 아니라 망 필터임을 확인했고, 다른 망으로 전환해 응답을 받아 `assets/mock/` 에 저장했다. 이후 파싱 작업은 저장한 응답을 고정 입력으로 삼아 망 상태와 무관하게 진행했다.
- **과제 2 의 Lucy 캔버스는 iPhone 12 Pro(390 × 844)로 두었다.** 시안 기준 프레임은 393 × 852 지만 Lucy 의 해상도 목록에 그 크기가 없다. 393 × 852 는 Figma 값을 읽어낸 **기준 프레임이지 캔버스 크기가 아니므로**(`rules/ui.md`), 고정으로 맞춰야 하는 여백 · 폰트 크기 · 아이콘 크기는 시안 값을 그대로 넣고 화면을 채우는 폭만 캔버스에 맡겼다. 가로 3pt · 세로 8pt 차이는 결과에 드러나지 않는다.
- **당겨서 새로고침은 헤더의 새로고침 버튼과 같은 동작을 부른다.** 선택 항목이라 새 경로를 만드는 대신 `RefreshIndicator` 의 `onRefresh` 를 기존 `WatchlistViewModel.refresh` 에 그대로 연결했다. 중복 요청 가드(`_isRefreshing`)를 두 진입점이 함께 타므로 버튼과 당기기를 연달아 해도 요청이 겹치지 않는다. 행이 적어 스크롤이 생기지 않는 상태에서도 당길 수 있어야 해서 `AlwaysScrollableScrollPhysics` 를 고정했다.
- **과제 2 의 행을 컴포넌트로 분리하지 않고 ListView 안에 직접 그렸다.** 과제는 "행은 컴포넌트로 분리해 재사용"을 요구하고, 그에 맞춰 `AlertRow` 컴포넌트와 노출 변수(`name` · `priceLabel` · `side`) 설계까지 마쳤다. 막힌 지점은 **컴포넌트 변수가 리스트의 행 스코프를 타는지**였다. `IteratorObjet.setState(i, fn)` 문서는 "바인딩된 프로퍼티"를 갱신한다고만 적고 컴포넌트 변수까지 같은 스코프인지는 말하지 않는데, 이걸 확인하는 데 시간을 다 쓰면 "등록하면 실제로 목록에 추가된다"는 **동작 요구를 못 채울 위험**이 컸다. 과제가 "그려두기만 하면 부족"이라고 따로 강조한 쪽을 택해, 행을 ListView 의 반복 자식으로 직접 두고 `setState` 안에서 `txtName` · `txtPrice` 를 갱신했다. 컴포넌트 파일은 지우지 않고 남겨 뒀다.
- **과제 2 의 색을 Lucy 디자인 토큰이 아니라 ARGB 값으로 직접 넣었다.** 새로 만든 Lucy 프로젝트에는 색 토큰이 하나도 없었다(`assets/theme/text_styles.json` 이 빈 배열). `setTextColor` 는 토큰 이름을 받으므로 토큰을 먼저 정의해야 이름이 먹는데, 마감 당일이라 토큰 체계를 새로 세우는 대신 과제 1 의 `app/lib/theme/` 값을 그대로 ARGB 로 옮겼다(`price/up/text` = `#FFFF5B5B`, `price/down/text` = `#FF4D9BEE`). **두 과제의 색이 같은 출처에서 나온다는 점은 유지**했고, 토큰 정의는 선택 항목이라 미뤘다.
- **과제 2 의 다이얼로그를 별도 페이지로 만들었다.** `targetAlertAdd` 를 페이지로 두고 `$form.openDialog("targetAlertAdd", ...)` 로 연다. 닫기는 **`$ownerForm.closeDialog(result)`** 다 — Lucy 튜토리얼 프로젝트의 `dialog.lfp` 가 그렇게 쓰고 있었다. 열린 폼 자신이 아니라 **연 쪽**의 폼에 닫기를 요청하는 형태다. 결과 객체를 그대로 콜백으로 돌려주므로 등록 값 전달과 `x` 취소(= `null`)를 한 경로로 처리했다.

## AI 활용 범위

Claude Code 를 설계 검토 · 구현 · 문서 작성에 활용했다. 아키텍처 결정과 그 근거는 직접 판단해 [`ARCHITECTURE.md`](docs/ARCHITECTURE.md) 에 남겼고, 생성된 코드는 전부 읽고 이해한 뒤 반영했다.
